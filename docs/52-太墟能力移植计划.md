## 第 1 阶段（已完成）

问题：部分中转站在正文发完后直接断连，不补 `[DONE]` 也不给 `finish_reason`；
上层把「没有结束标记」当成网络中断，回滚整段回答并重发，界面表现为「说完又整段重来」，
供应商侧还会记两次调用。

改法：`processStreamingResponse` 结束时，若未确认完成但已收到过数据（`chunkCount > 0`），
按正常结束处理并打日志；完全没有数据才抛 `IOException` 走重试。

验收：用中转站跑一次长回答，确认不再出现整段重发。

## 第 2 阶段要点

- 阈值：默认 8 KB，超过即落盘到 `files/artifacts/tool-output/<timestamp>-<tool>.txt`
- 回给模型的内容：前 2 KB 预览 + 文件路径 + 总字节数 + 「用 read_file 分页读取」
- 历史里保留落盘标记，重启后仍可回读
- 需要同时改：工具结果格式化处、历史持久化、`read_file` 是否支持分页

## 第 3 阶段要点

- 预算按「模型上下文窗口 × 0.7」计算，超出时从最老的一轮开始压缩
- 压缩产物是「摘要块」，要标记来源轮次，避免和原始消息混淆
- 首字延迟敏感：只在发送前算一次，不放进流式路径

## 第 4 阶段要点

- 会话表加 `parentId` + `forkedAtMessageId`，分叉不复制消息体，只引用
- 回退用「逻辑截断」而不是删消息，保留可恢复性
- 工作区快照只记录 agent 写过的文件，按轮次存差异

## 第 5 阶段要点

- 先有稳定的工具注册与权限，再谈子 agent
- 预算、写路径租约、结果分页三者缺一不可，否则并行写入会打架
