# 54 - GitHub 构建与设备安装流程

这份文档把「改代码 → push → CI 出包 → 装到手机 → 验证」这条链路固定下来，
目的是换人或换 agent 接手时不用重新试错。配套脚本在 `tools/ci/`。

## TL;DR

```bash
cd ~/_operit-src                      # 设备上的工作克隆
# 改代码
git add -A && git commit -m "fix: ..."

export GITHUB_TOKEN=github_pat_xxx    # 只放环境变量，绝不写进仓库
GIT_TERMINAL_PROMPT=0 git -c credential.helper= \
  push https://x-access-token:${GITHUB_TOKEN}@github.com/yihangoodmmm-byte/operit-fork.git HEAD:main

tools/ci/fetch_apk.sh --sha $(git rev-parse --short HEAD)   # 等 20~40 分钟，取包到 dist/
tools/ci/android_install_and_aot.sh dist/app-debug.apk        # 装 + 强制 AOT
```

## 1. 仓库、分支、推送

| 项 | 值 |
| --- | --- |
| 远程 | `https://github.com/yihangoodmmm-byte/operit-fork.git` |
| 本地工作克隆 | 设备沙箱内 `~/_operit-src`（不是 `/storage/emulated/0/...` 里那份拷贝） |
| 推送方式 | 本地分支 `persona` → 远程 `main` |
| 包名 | `com.inmyfeelings.ai.debug`（debug 变体，带 `.debug` 后缀） |

推送必须内联 token，本机没有 credential helper：

```bash
GIT_TERMINAL_PROMPT=0 git -c credential.helper= \
  push https://x-access-token:${GITHUB_TOKEN}@github.com/yihangoodmmm-byte/operit-fork.git HEAD:main
```

坑：

- 只写 `https://TOKEN@github.com/...` 会报 `could not read Username for 'https://github.com'`。必须用 `x-access-token:TOKEN@` 这种形式。
- 这台设备上 TLS 偶发 `send-pack: unexpected disconnect`，重试 2~3 次即可，不要改代码。

## 2. push 会触发什么

一次 push 可能同时触发两个 workflow，**它们互不阻塞**：

| workflow | 触发 | 干什么 | 出不出包 |
| --- | --- | --- | --- |
| `android-tests.yml` | push（paths 过滤） | 编译主代码 + 跑 JVM 单元测试 | **不出包** |
| `android-build.yml` | push（paths 过滤）或手动 dispatch | 完整出 APK | 出 |

所以 **Android Tests 红不等于包坏了**，先看 Android Build 的结论。

paths 过滤（两个 workflow 基本一致）：改这些会触发构建 ——
`app/**`、`*.gradle.kts`、`gradle.properties`、`gradle/**`、`ci/script/**`（仅列出的两个文件）、
`cmake/**`、`terminal/**`、`tools/native_ripgrep/**`、`web-chat/**`、`package*.json`、以及 workflow 文件本身。

改 `docs/**`、`tools/ci/**`、`README` **不会**触发构建，别指望顺便出包。

`concurrency: cancel-in-progress` 打开着：同一分支连续 push，前一次会被取消，
所以最后一次 push 才是有效构建。

## 3. 构建耗时与产物形态

- 20~40 分钟。去掉 debuggable 之后比之前慢 8~10 分钟（release-like 变体还要跑 L8 脱糖、符号 strip、`lintVital`）。
- artifact 名：`operit-android-<run_number>`，zip 约 **338 MB**。
- 解开后是 `apk/debug/app-debug.apk`，约 **347 MB**。
- artifact 只保留 3 天，要留就拷到 `dist/`。

## 4. 取包

用脚本，不要手搓 curl：

```bash
tools/ci/fetch_apk.sh                       # main 上最新一次成功的 Build
tools/ci/fetch_apk.sh --sha c0bb804         # 指定提交（推荐，避免抓到旧包）
tools/ci/fetch_apk.sh --run 41630708160     # 指定 run
tools/ci/fetch_apk.sh --dry-run             # 只打印 run/artifact/大小
```

脚本内部踩过的坑（改脚本时别踩回去）：

1. 里面会**等** run 跑完（30 秒一次轮询），不用自己盯着。
2. 下载必须带 `Authorization: token`，并且 `curl -L`（`archive_download_url` 会 302 到 objects.githubusercontent.com）。
3. 传输经常 `unexpected eof` 截断。用 `curl -C -` 循环续传，直到本地字节数等于 artifacts API 里的 `size_in_bytes` **才结束**。只看 HTTP 200 会拿到半个包。

## 5. 安装 + 强制 AOT（最重要的一步）

```bash
tools/ci/android_install_and_aot.sh dist/app-debug.apk
```

脚本做四件事：`am force-stop` → `pm install -r -d` → `cmd package compile -m speed -f <pkg>` → 打印 ART 状态。

### 为什么必须手动 AOT

- `debuggable` 的包，ART **只 verify 不生成机器码**（`status=run-from-apk`），Compose 每一帧都在解释器里跑。
  实测（PYS110 / Android 16 / 120Hz）：掉帧 30.2%、p90 38ms、Slow UI thread 12 帧，但 GPU 只有 4~6ms —— 瓶颈全在主线程。
- 我们已把 `app/build.gradle.kts` 里 debug 变体设成 `isDebuggable = false`，包名和签名不变，可以覆盖安装保数据。
- 但非 debuggable 的包**安装时默认也只给 `verify [reason=install]`**，靠系统后台 dexopt 慢慢变成 speed-profile。
  想立刻顺滑就必须跑一次编译命令，验证：

```bash
su -c "dumpsys package com.inmyfeelings.ai.debug | grep -E 'arm64: \[status'"
# 期望: arm64: [status=speed] [reason=cmdline] [primary-abi]
```

**每次装新包都要重做**，否则观感还是「有点拖」。

## 6. 装完怎么判断快不快

```bash
su -c "dumpsys gfxinfo com.inmyfeelings.ai.debug reset"
# 连续滑动几下（或用 input swipe 批量）
su -c "dumpsys gfxinfo com.inmyfeelings.ai.debug | head -24"
```

判读规则：

- `50th/90th gpu percentile` 很低但 `Slow UI thread` 多 → 主线程问题（重组 / 解释执行），不是渲染。
- `90th percentile` 超过 16.7ms 就会在 60Hz 上掉帧；这块屏 120Hz，预算只有 8.3ms。
- 参考基线（同一段 20 次快速滑动）：

| | 修前（debuggable） | 修后（AOT speed） |
| --- | --- | --- |
| 掉帧率 | 30.2% | 5.9% |
| Slow UI thread | 12 | 1 |
| 50th / 90th 帧耗时 | 11ms / 38ms | 8ms / 13ms |

注意：聊天页消息不多时列表根本不可滚动，滑动不会产生连续重绘，帧数统计会显得很小 —— 要看帧耗时分布，别只看 `Total frames rendered`。

## 7. 常见失败与处理

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `lintVitalDebug FAILED` + `ExtraTranslation` | 只有 **非 debuggable** 变体才跑 lintVital；`values-xx/strings.xml` 里有默认语言没有的字符串 | 删孤儿字符串或补进 `values/strings.xml`。可用 `ci/script/check_localizations.py` 先扫 |
| `No space left on device` | runner 盘不够：release-like 变体额外跑 L8 脱糖 / strip / lint | 已在 workflow 加 `Free disk space` 步骤（删 dotnet/swift/ghc/emulator/system-images，只留本次的 NDK+CMake）。再现就再扩清理范围 |
| `compileDebugUnitTestKotlin FAILED` | 上游遗留测试引用了本 fork 不存在的符号 | 已删除 `XaiProviderReasoningTest`、`DeepseekProviderMediaRoleTest`。新增测试必须能编译 |
| `could not read Username` | 推送 URL 形式不对 | 见 §1 |
| 下载到一半 `unexpected eof` | 传输截断 | 见 §4，用脚本 |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | CI 每次 run 用 runner 上自动生成的 debug keystore，签名可能变 | 目前实测可覆盖安装；真变了只能卸载（丢数据），或把 keystore 缓存进 Actions cache |
| 装完还是卡 | 忘了 AOT | 见 §5 |

## 8. 产物归档

- 脚本里的 `OUT_DIR` 默认是 **当前目录下的 `dist/`**。在 `~/_operit-src` 里跑就会落在克隆目录里；
  要交付给用户就显式指定：`OUT_DIR=/storage/emulated/0/inmyfeelings/inmyfeelings/dist tools/ci/fetch_apk.sh --sha xxx`。
- 统一放 `/storage/emulated/0/inmyfeelings/inmyfeelings/dist`，命名 `inmyfeelings-code-<版本>-<主题/用途>.apk`。
- 每次交付顺手记录：`aapt2 dump badging` 的头两行 + `sha256sum`。
- 大改之前打一份 bundle 到 `backups/<日期>/`。

## 9. 安全

- token 只走环境变量，**绝不**写进代码、文档、commit message。本文档里一律用 `${GITHUB_TOKEN}` 占位。
- 当前用的是 classic token（repo + workflow）。建议换成 fine-grained、仅这一个仓库、定期轮换；在聊天里贴过的 token 应当作已泄露处理。

## 10. 脚本索引

| 脚本 | 作用 |
| --- | --- |
| `tools/ci/fetch_apk.sh` | 等 run 完成 → 找到 `operit-android-*` artifact → 断点续传下载 → 解包 → 只留 APK |
| `tools/ci/android_install_and_aot.sh` | 覆盖安装 → 强制 `speed` AOT → 校验 ART 状态 |
